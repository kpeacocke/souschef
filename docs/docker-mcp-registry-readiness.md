## Container and deployment notes

- The image uses a digest-pinned Python Alpine base and UID/GID `1001:1001`; the production stage removes pip and does not include Poetry. Runtime MCP output was valid JSON-RPC on stdout, and the MCP tool registry exposed 105 tools.
- Container tests used `--cap-drop=ALL`, `--security-opt=no-new-privileges`, and `--network=none`. A mounted-workspace verifier could not be completed because the Docker daemon is isolated from this process's temporary host paths. Therefore mounted-directory read/write permissions and mounted-recipe conversion are **NOT VERIFIED here**.
- The build runs `apk upgrade` against the pinned Alpine branch. This refreshes OS packages but makes OS-package resolution time-dependent; the image is not fully reproducible at the OS-package level.
- The path containment helpers validate normalized and resolved paths, but filesystem races after validation still require OS-level permissions and a controlled mount. Mount only the intended workspace and give UID 1001 only the required access.
- No MCP tool performs remote host execution. AWX/AAP tools generate configuration; v2 deployment, rollback, and playbook validation are expressly unimplemented. GitHub agent-named tools only manage tracking labels/comments and can post visible comments. AI tools may send source content to configured external providers.
